# Algoritmo de corrección de deriva del reloj interno (TimeModel)

## Referencia normativa

IEC 62053-21:2020 §7.11 — Exactitud del reloj interno.

| Tipo de reloj | Límite |
|---|---|
| Reloj interno (cristal ESP32 40 MHz) | ±0.5 s/día |
| Reloj con corrección RTC (RV-3028) | ±0.5 s/24 h tras sincronización |

## Arquitectura

TimeModel es el responsable de convertir el tiempo del contador monotónico del ESP32 (`esp_timer_get_time`) en tiempo UTC corregido por deriva.

```
ktime (monotónico, hw timer) ─→ TimeModel.ktime_to_utc() ─→ UTC corregido
                                      ↑
                               drift_factor (ajustado por NTP/RTC)
```

## Parámetros

### TimeModel (metrology_insight/src/types.rs)

| Campo | Tipo | Descripción |
|---|---|---|
| `utc_at_boot_ns` | u64 | UTC verdadero en el arranque (desde SystemTime o RTC) |
| `ktime_at_boot_ns` | u64 | ktime en el arranque (monotónico) |
| `drift_factor` | f32 | Factor de corrección: UTC_transcurrido / ktime_transcurrido |
| `last_calibration_ktime_ns` | u64 | ktime de la última recalibración |

### MetrologyConfig (campos añadidos)

| Campo | Tipo | Descripción | Defecto |
|---|---|---|---|
| `rtc_drift_ppm` | f32 | Deriva del cristal en partes por millón (+ = rápido) | 0.0 |
| `rtc_temp_coeff_ppm_c` | f32 | Coeficiente térmico (ppm/°C) | 0.04 |
| `rtc_last_calibration_utc` | u64 | UTC (s) de la última calibración | 0 |

## Algoritmo

### Inicialización

```rust
let ktime_ns = esp_timer_get_time() * 1000; // μs → ns
let utc_ns = SystemTime::now() * 1_000_000; // ms → ns
TimeModel::init_from_system(utc_ns, ktime_ns);
```

Establece `utc_at_boot_ns = utc_ns`, `ktime_at_boot_ns = ktime_ns`, `drift_factor = 1.0`.

Si hay un valor configurado de `rtc_drift_ppm` (p.ej. +20 ppm), se aplica:

```rust
drift_factor = 1.0 + rtc_drift_ppm / 1_000_000.0;
```

### Conversión ktime → UTC

```rust
fn ktime_to_utc(ktime_ns: u64) -> u64 {
    delta_ktime = ktime_ns - ktime_at_boot_ns;
    delta_utc = delta_ktime * drift_factor;
    utc_at_boot_ns + delta_utc
}
```

### Recalibración por NTP

Cuando se recibe una referencia UTC fiable (NTP, comando manual):

```rust
fn recalibrate(utc_new_ns, ktime_new_ns) {
    delta_ktime = ktime_new_ns - last_calibration_ktime_ns;
    delta_utc = utc_new_ns - utc_at_boot_ns;
    if delta_ktime > 1 ms {
        drift_factor = delta_utc / delta_ktime;
        last_calibration_ktime_ns = ktime_new_ns;
    }
}
```

La recalibración solo se ejecuta si `delta_ktime > 1 ms` para evitar división por ruido.

## Límites del cristal ESP32

- Cristal externo típico: ±10 a ±30 ppm a 25 °C
- Coeficiente térmico: ~0.04 ppm/°C
- Sin corrección: 20 ppm × 86400 s = 1.73 s/día → **no cumple** ±0.5 s
- Con corrección por NTP cada 12 h: error máx. ~0.86 s (20 ppm × 12 h)
- Con RTC RV-3028 (±1 ppm): 1 ppm × 86400 s = 0.086 s/día → **cumple**

## Flujo de recalibración

1. **Network task** detecta sincronización NTP completa
2. **Command task** recibe `SystemCommand::RtcRecalibrate`
3. Activa `TIME_RECALIBRATE_FLAG` (AtomicBool)
4. **DSP task** detecta flag en su ciclo, llama `measurements.recalibrate_time_model()`
5. `TimeModel::recalibrate()` computa nuevo `drift_factor`
6. Todas las señales posteriores usan `ktime_to_utc()` con el factor actualizado

## Comandos disponibles

| Console | API | MQTT | Efecto |
|---|---|---|---|
| `rtc status` | `GET /api/v1/time/getTime` | `/telemetry/time/status` | Muestra tiempo, deriva, NTP |
| `rtc setdrift <ppm>` | `POST /api/v1/set/time/config` | `/cmd/time/config` | Ajusta deriva en ppm |
| `rtc recalibrate` | — | — | Recalibra TimeModel ahora |
